# Swing Webアプリケーション 限定公開ガイド

## 現在の状況

現在のFlask Webアプリケーション（src/ui/web.py）には認証機能が実装されていません。このドキュメントでは、限られたメンバーにのみアプリケーションを公開するための方法を、簡単な順に説明します。

## 限定公開の方法（簡単な順）

### 1. 🟢 Basic認証（最も簡単）

**概要**: Webサーバーレベルで認証を設定する最も簡単な方法

**実装方法**:
- **nginx/Apache**: 設定ファイルで認証を追加
- **開発サーバー**: Flask-HTTPAuthを使用

```python
# Flask-HTTPAuthを使用した例
from flask_httpauth import HTTPBasicAuth

auth = HTTPBasicAuth()

users = {
    "admin": "password123",  # 実際にはハッシュ化して保存
    "user1": "pass456"
}

@auth.verify_password
def verify_password(username, password):
    if username in users and users[username] == password:
        return username

@app.before_request
@auth.login_required
def before_request():
    pass
```

**メリット**:
- 実装が非常に簡単
- 既存コードの変更が最小限
- すぐに導入可能

**デメリット**:
- HTTPSが必須（パスワードが平文で送信される）
- ユーザー管理が簡易的

### 2. 🟡 VPNまたはプライベートネットワーク

**概要**: ネットワークレベルでアクセスを制限

**実装方法**:
- 社内ネットワークのみでアクセス可能に設定
- VPNサーバーを構築してアクセス制限
- IPアドレスホワイトリスト

```python
# IPアドレス制限の例
from functools import wraps
from flask import request, abort

ALLOWED_IPS = ['192.168.1.100', '192.168.1.101']

def limit_remote_addr(f):
    @wraps(f)
    def decorated_function(*args, **kwargs):
        if request.remote_addr not in ALLOWED_IPS:
            abort(403)  # Forbidden
        return f(*args, **kwargs)
    return decorated_function

@app.before_request
def limit_remote_addr():
    if request.remote_addr not in ALLOWED_IPS:
        abort(403)
```

**メリット**:
- アプリケーション側の変更不要
- 高いセキュリティ
- 既存の社内インフラを活用可能

**デメリット**:
- 外部からのアクセスが困難
- VPN設定が必要な場合がある

### 3. 🟡 Flask-Loginによる認証実装

**概要**: 既にインストール済みのFlask-Loginを活用した本格的な認証

**実装方法**:
```python
from flask_login import LoginManager, UserMixin, login_user, login_required, logout_user

# 認証設定
login_manager = LoginManager()
login_manager.init_app(app)
login_manager.login_view = 'login'

# ユーザークラス
class User(UserMixin):
    def __init__(self, id):
        self.id = id

# ユーザー情報（実際はデータベースやJSONファイルで管理）
users = {
    'user1': {'password': 'hash_of_password'},
    'user2': {'password': 'hash_of_password'}
}

@login_manager.user_loader
def load_user(user_id):
    return User(user_id) if user_id in users else None

# ログインエンドポイント
@app.route('/login', methods=['GET', 'POST'])
def login():
    # ログインフォーム処理
    pass

# 保護されたルート
@app.route('/dashboard')
@login_required
def dashboard():
    return render_template('dashboard.html')
```

**メリット**:
- 本格的なユーザー管理
- セッション管理
- Remember Me機能などの高度な機能

**デメリット**:
- 実装に時間がかかる
- ログイン画面の作成が必要

### 4. 🔴 クラウドサービスの認証機能

**概要**: AWS Cognito、Auth0、Firebase Authenticationなどを利用

**メリット**:
- プロフェッショナルな認証システム
- 多要素認証対応
- ユーザー管理UI提供

**デメリット**:
- 設定が複雑
- コストがかかる場合がある
- 外部サービス依存

## 推奨される実装手順

### 最も簡単に始める場合（Basic認証）

1. **requirements.txtに追加**:
```
Flask-HTTPAuth>=4.8.0
```

2. **src/ui/web.pyの先頭に追加**:
```python
from flask_httpauth import HTTPBasicAuth
from werkzeug.security import generate_password_hash, check_password_hash

auth = HTTPBasicAuth()

# ユーザー情報をconfig/login.jsonから読み込む
import json
try:
    with open('config/login.json', 'r') as f:
        users = json.load(f)
except FileNotFoundError:
    users = {"admin": generate_password_hash("changeme")}
```

3. **config/login.jsonを作成**:
```json
{
  "user1": "$pbkdf2-sha256$...",
  "user2": "$pbkdf2-sha256$..."
}
```

4. **パスワードハッシュ生成スクリプト**:
```python
# scripts/generate_password_hash.py
from werkzeug.security import generate_password_hash
import sys

if len(sys.argv) != 2:
    print("Usage: python generate_password_hash.py <password>")
    sys.exit(1)

print(generate_password_hash(sys.argv[1]))
```

### セキュリティ上の注意事項

1. **HTTPS化は必須**
   - Let's Encryptで無料SSL証明書を取得
   - nginx/Apacheでリバースプロキシ設定

2. **環境変数の使用**:
```python
app.secret_key = os.environ.get('SECRET_KEY') or 'dev-key-change-this'
```

3. **本番環境での設定**:
   - デバッグモードを無効化
   - 適切なログ設定
   - エラーページのカスタマイズ
